- Deviations from the design snippet (each one fixes a bug the snippet would have):
  - **Server nulls.** The API sends `"campaign_state": null` and `"materials": null`; `ProjectSchema` rejects `null` for optional fields, so every server project would have been "invalid". `projectFromServer()` drops those nulls before `readProject`.
  - **Lost save.** In the snippet, a state saved while a PUT is in flight is not sent until the next change. Here it is sent right after the in-flight PUT finishes.
  - **Pending per project.** One pending slot per project id instead of one global slot, so switching projects inside the 1.5 s window cannot drop the first project's progress on the server.
  - **Same timestamp.** `saveCampaignState` stamps the local and the server copy with one `updatedAt` (F1 note); the POST body is the record the local store wrote, so ids and timestamps match.
  - **2xx with bad body on create** returns the local record (it is saved on both sides) instead of "Server returned invalid data".
  - First retry after 5 s (the snippet doubled before the first retry, so it started at 10 s).
- Kept from the design: a non-409 refusal on create (e.g. 422 cap, 5xx) returns `{ ok: false }` with "kept on this device"; the local copy stays and the sync check retries it.
